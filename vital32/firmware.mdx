Vital32 firmware is written in **Arduino C++ on the ESP32 Arduino Core** (Espressif v2.x). The entire sensing, inference, and transmission pipeline runs within a single-core main loop clocked at **50 Hz** (one tick every 20 ms). A distributed tick scheduler gates each sensor or computation block to the minimum polling rate its physics and algorithm require — this prevents I²C bus saturation, reduces unnecessary wake cycles on slow sensors, and aligns Firebase writes to meaningful biological windows.

---

## Tick Scheduler Design

The scheduler uses `millis()` modulo arithmetic to trigger blocks at four distinct cadences without blocking the main loop or using RTOS tasks. This keeps the firmware portable, debuggable, and deterministic on a single core.

```cpp
void loop() {
  uint32_t t = millis();

  // ─────────────────────────────────────────────
  // Every tick (20 ms) — 50 Hz:
  // ─────────────────────────────────────────────
  readMPU6050();           // accel + gyro at 50 Hz for fall detection
  runFallDetector();

  // ─────────────────────────────────────────────
  // Every 1 second — 1 Hz:
  // ─────────────────────────────────────────────
  if (t % 1000 == 0) {
    readMAX30102();        // heart rate + SpO₂ from PPG waveform
    readMLX90614();        // IR skin surface temperature
    readGSR();             // galvanic skin response (ADC GPIO 35)
    calculateHRV();        // RMSSD + LF/HF from RR interval buffer
    runAnomalyScorer();    // Isolation Forest on fused biomarker vector
    updateOLED();          // refresh SSD1306 display with latest vitals
  }

  // ─────────────────────────────────────────────
  // Every 5 seconds — 0.2 Hz:
  // ─────────────────────────────────────────────
  if (t % 5000 == 0) {
    readBME688();          // VOC index, humidity, pressure
    readVEML6075();        // UVA + UVB irradiance, UV index
    readBIA();             // bioelectrical impedance (AD5933 sweep)
    runSeizureDetector();  // LSTM inference on rolling gyro+PPG window
  }

  // ─────────────────────────────────────────────
  // Every 30 seconds:
  // ─────────────────────────────────────────────
  if (t % 30000 == 0) {
    runBioAgeModel();      // fused biological age estimate
    writeToFirebase();     // commit full state object to Realtime DB
  }
}
```

## Tick Rate Rationale

Each cadence is derived from the physical response time of the underlying biosignal and the algorithm that consumes it.

### 50 Hz — Inertial (MPU6050) and Fall Detection

Human free-fall events last between 100 ms and 400 ms. Sampling the accelerometer at 50 Hz gives a sample every 20 ms — sufficient to detect the characteristic sub-0.4g freefall phase within the first two samples of its onset. At lower rates (e.g., 10 Hz / 100 ms per sample), the freefall phase of a rapid forward stumble may be missed entirely. The MPU6050 onboard FIFO buffers readings between polls, so no samples are dropped between loop iterations.

### 1 Hz — Heart Rate, SpO₂, Temperature, GSR, and HRV

PPG waveform analysis for heart rate and SpO₂ requires accumulating enough cardiac cycles to compute a stable average. The MAX30102 integration window is typically 0.5–1.0 seconds. Skin temperature via MLX90614 changes on a timescale of seconds; sub-second polling adds thermal noise without improving resolution. GSR fluctuations relevant to sympathetic activation occur over 2–30 seconds; 1 Hz sampling provides ample temporal resolution while keeping the ADC read overhead minimal. HRV RMSSD is computed from the RR interval series accumulated across the 1-second window.

### 5 Seconds — Gas Sensor, UV, BIA, and LSTM

The BME688 gas sensor requires a burn-in stabilisation period of several seconds per reading; polling it faster than once every 5 seconds yields artificially correlated readings. UV index changes meaningfully only when the user moves between environments — 5-second resolution is sufficient. The AD5933 bioelectrical impedance sweep takes approximately 1.5–2.5 seconds at the configured frequency range; it cannot be run faster without truncating the sweep. Critically, the pre-seizure LSTM operates on a rolling window assembled from MPU6050 and PPG data collected at 50 Hz and 1 Hz respectively — the 5-second inference trigger matches the temporal receptive field of the LSTM architecture.

### 30 Seconds — Biological Age and Firebase Write

Biological age is a composite derived from multiple slowly-evolving signals (HRV trend, SpO₂ trend, BIA hydration) and is statistically meaningless at sub-minute resolution. Batching Firebase writes to 30 seconds reduces Wi-Fi radio duty cycle by approximately 90% compared to per-second transmission, directly extending battery life. Instantaneous event triggers (fall detected, anomaly threshold crossed, seizure pre-cursor flagged) bypass this cadence and fire an immediate `writeToFirebase()` call.

## Firebase Write Schema

Each 30-second write (or event-triggered write) commits the following JSON object to `/vital32/{deviceId}/latest` in the Firebase Realtime Database:

```json
{
  "timestamp": 1718200000000,
  "heart_rate": 72,
  "spo2": 98.2,
  "skin_temp_c": 34.1,
  "hrv_rmssd": 42.7,
  "hrv_lf_hf": 1.83,
  "gsr_raw": 2048,
  "gsr_normalised": 0.61,
  "cortisol_est": 0.74,
  "voc_index": 102,
  "humidity_pct": 58.3,
  "uv_index": 3.1,
  "bia_hydration_score": 0.68,
  "bio_age": 41.2,
  "anomaly_score": 0.13,
  "seizure_risk": 0.04,
  "fall_detected": false,
  "accel_magnitude": 0.98,
  "wifi_rssi": -62
}
```

Fields prefixed with `_est` or `_score` are model outputs, not raw sensor readings. Downstream subsystems (HollowRover, SphereAI, HollowCore) subscribe to this node and react to state changes without polling.

## I²C Bus Management

With seven devices on a single bus, the firmware serialises all I²C transactions. No two sensors are read concurrently. The read order within each tick block follows address order (lowest to highest) to produce consistent bus arbitration timing: `AD5933 → VEML6075 → SSD1306 → MAX30102 → MLX90614 → MPU6050 → BME688`.

Each read is wrapped in a timeout guard:

```cpp
bool i2cReadWithTimeout(uint8_t addr, uint8_t* buf, size_t len, uint32_t timeout_ms) {
  Wire.beginTransmission(addr);
  if (Wire.endTransmission(false) != 0) return false;  // device not ACKing
  uint32_t start = millis();
  Wire.requestFrom(addr, len);
  while (Wire.available() < (int)len) {
    if (millis() - start > timeout_ms) return false;
  }
  for (size_t i = 0; i < len; i++) buf[i] = Wire.read();
  return true;
}
```

If a sensor fails to ACK (e.g., intermittent contact in a wrist-worn device), its last valid reading is carried forward for up to 5 seconds before being flagged as `STALE` in the Firebase write.

<Tip>
  Disable the ESP32 task watchdog timer during the first I²C bus scan at boot (`esp_task_wdt_delete(NULL)` before the scan loop, then re-enable it after). Long I²C clock-stretching by the BME688 during its gas sensor heater calibration sequence can exceed the default 3-second watchdog threshold and trigger a spurious reset before the device is correctly initialised.
</Tip>

## OTA Firmware Updates

Vital32 supports over-the-air firmware updates via the Arduino OTA library. The update endpoint is checked on every Wi-Fi reconnect. During an OTA write, all sensor reads are suspended and the OLED displays a progress bar. The Firebase state object is set to `{"status": "updating"}` for the duration.

```cpp
ArduinoOTA.onStart([]() {
  allSensorsSuspend();
  display.showUpdateScreen();
  Firebase.setString(fbdo, "/vital32/" + deviceId + "/status", "updating");
});

ArduinoOTA.onEnd([]() {
  Firebase.setString(fbdo, "/vital32/" + deviceId + "/status", "online");
  ESP.restart();
});
```
