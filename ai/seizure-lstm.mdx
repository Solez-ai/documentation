<Info>
  The Pre-Seizure LSTM estimates **seizure probability 30 minutes before onset** by learning temporal patterns in HRV, accelerometer, skin temperature, GSR, and SpO2 signals. It runs on the Vital32 ESP32 at every 5-second firmware tick via TFLite Micro.
</Info>

## Clinical Motivation

Epileptic seizures are preceded by a **pre-ictal state** — a period of measurable neurological and autonomic change that begins minutes to hours before the ictal event. Studies have demonstrated that:

- **Heart rate variability** shifts measurably in the 30–60 minutes preceding generalized tonic-clonic seizures (Jeppesen et al., 2014)
- **Galvanic skin response** increases in the pre-ictal window due to heightened sympathetic tone
- **Accelerometer patterns** capture subtle tonic pre-movements that precede the overt convulsive phase

LifeSphere exploits these pre-ictal biomarker changes using a wearable-only sensor suite — no scalp EEG is required. The model produces a **seizure probability estimate** $\hat{y} \in [0,1]$ every 5 seconds from a sliding 5-minute temporal window.

## Training Datasets

The model is trained on two publicly available datasets from PhysioNet and MIT:

| Dataset | Source | Description |
|---|---|---|
| CHB-MIT Scalp EEG | Shoeb, MIT (2009); PhysioNet | 22 pediatric patients, 916 seizures, multi-channel EEG. HRV/accel proxies derived from ECG channels. |
| Epilepsy iEEG Prediction | Kaggle/PhysioNet 2014 | Intracranial EEG clips (preictal vs. interictal). Feature-extracted to HRV and motion surrogates. |

<Warning>
  The training datasets are EEG-derived. LifeSphere extracts HRV, motion, and autonomic surrogate features from these datasets to bridge to the wearable sensor domain. The model is further **fine-tuned on individual user data** as seizure history accumulates in Firebase over time.
</Warning>

Because both datasets contain labeled pre-ictal and interictal windows, the training problem is formulated as **binary sequence classification**:

$$y = \begin{cases} 1 & \text{pre-ictal window (seizure within 30 min)} \\ 0 & \text{interictal window (no seizure)} \end{cases}$$

---

## Input Representation

The model consumes **5-minute rolling windows** sampled at 1 Hz, giving an input tensor of shape:

$$\mathbf{X} \in \mathbb{R}^{300 \times 5}$$

where 300 is the number of time steps (300 seconds at 1 Hz) and 5 is the number of input features:

| Feature Index | Feature | Derivation |
|---|---|---|
| 0 | RR interval (HRV) | Peak-to-peak from PPG waveform (ms) |
| 1 | Accelerometer magnitude | $\|\mathbf{a}\|_2 = \sqrt{a_x^2 + a_y^2 + a_z^2}$ (g) |
| 2 | Skin temperature $T_{\text{skin}}$ | MLX90614 IR thermometer (°C) |
| 3 | Galvanic skin response (GSR) | Grove GSR sensor (µS) |
| 4 | Blood oxygen $s_{O_2}$ | MAX30102 PPG (%) |

Each feature stream is **z-score normalized** within the current rolling window to remove slow drift and inter-session baseline shifts:

$$\tilde{x}_{t,i} = \frac{x_{t,i} - \bar{x}_i}{\sigma_i}, \quad t \in [1, 300]$$

## Model Architecture

The network is a stacked bidirectional LSTM followed by two Dense layers:

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense, Dropout

def build_seizure_model() -> tf.keras.Model:
    """
    Construct the pre-seizure LSTM architecture.

    Input shape  : (300, 5) — 5-minute window at 1 Hz, 5 features
    Output shape : (1,)     — seizure probability in [0, 1]
    """
    model = Sequential([
        # First LSTM layer: captures short-range temporal dependencies
        # return_sequences=True feeds the full sequence to the second LSTM
        LSTM(64, input_shape=(300, 5), return_sequences=True),
        Dropout(0.3),

        # Second LSTM layer: compresses temporal sequence to a fixed-length
        # context vector; return_sequences=False collapses the time axis
        LSTM(32, return_sequences=False),
        Dropout(0.3),

        # Classification head
        Dense(16, activation='relu'),
        Dense(1, activation='sigmoid')   # seizure probability ŷ ∈ [0, 1]
    ])

    model.compile(
        optimizer='adam',
        loss='binary_crossentropy',
        metrics=['accuracy', 'AUC']
    )
    return model
```

### Layer-by-Layer Rationale

**LSTM(64, return_sequences=True)**
The first LSTM layer has 64 hidden units and preserves the full temporal output sequence. Its cell state $\mathbf{c}_t$ accumulates evidence across the 300-step window, learning to weight recent HRV and GSR fluctuations against their historical context within the 5-minute window.

**LSTM(32, return_sequences=False)**
The second LSTM layer compresses the sequence into a single 32-dimensional context vector. This hierarchical compression is analogous to a temporal convolutional stack — the first layer captures fine-grained oscillatory patterns, the second layer captures coarser pre-ictal trends spanning multiple minutes.

**Dropout(0.3)**
Applied after each LSTM layer. Standard recurrent dropout is not used here; instead, the dropout mask operates on the **output** of each LSTM layer. This prevents the model from over-fitting to an individual patient's idiosyncratic pre-ictal signature, which is critical given the small per-patient sample sizes in CHB-MIT.

**Dense(16, relu) → Dense(1, sigmoid)**
The classification head maps the 32-dimensional context vector to a scalar probability. The intermediate Dense(16) layer provides one level of nonlinear mixing before the final sigmoid activation.

## Loss Function

Training minimizes the **binary cross-entropy loss** over the labeled pre-ictal/interictal windows:

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N}\left[y_i \log(\hat{y}_i) + (1 - y_i)\log(1 - \hat{y}_i)\right]$$

where $y_i \in \{0, 1\}$ is the ground-truth label and $\hat{y}_i \in [0, 1]$ is the model's predicted seizure probability for window $i$. The AUC metric is monitored alongside accuracy because the dataset is **class-imbalanced** — pre-ictal windows represent a small fraction of total recording time.

To address class imbalance, the training loop applies **class weighting**:

$$w_{\text{pre-ictal}} = \frac{N_{\text{total}}}{2 \cdot N_{\text{pre-ictal}}}, \qquad w_{\text{interictal}} = \frac{N_{\text{total}}}{2 \cdot N_{\text{interictal}}}$$

## Why LSTM Over Feedforward Networks

Feedforward networks treat each 30-second snapshot as **stationary and exchangeable** — they cannot represent the sequential ordering of biomarker changes. The pre-ictal state is defined precisely by its **temporal structure**: HRV begins to decrease, then GSR rises, then accelerometer variance increases, in a consistent causal ordering.

LSTM networks maintain an explicit **cell state** $\mathbf{c}_t$ that propagates information across arbitrary time lags, governed by learned input, forget, and output gates:

$$\mathbf{f}_t = \sigma(\mathbf{W}_f [\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_f)$$
$$\mathbf{i}_t = \sigma(\mathbf{W}_i [\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_i)$$
$$\tilde{\mathbf{c}}_t = \tanh(\mathbf{W}_c [\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_c)$$
$$\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t$$
$$\mathbf{h}_t = \mathbf{o}_t \odot \tanh(\mathbf{c}_t)$$

This gating mechanism allows the network to selectively **remember** an anomalous HRV depression from 4 minutes ago while processing the current accelerometer reading — a capability inaccessible to any feedforward architecture operating on a single feature vector.

## Detection Threshold

$$\hat{y} > 0.85 \implies \texttt{dispatch\_seizure\_protocol()}$$

The 0.85 threshold was selected by maximizing the **F1 score** on a held-out validation set, prioritizing recall (minimizing missed seizures) over precision (tolerating some false alarms). When the threshold is crossed:

1. The SphereAI system instructs the HollowRover to pre-position itself adjacent to the user
2. A cushion-deployment alert is dispatched to the Rover's servo mechanism
3. Firebase Cloud Messaging sends a priority alert to the caregiver's mobile device
4. A 30-second biometric snapshot is archived to `/lifesphere/{device_id}/events/seizure/{timestamp}`

<Tip>
  The cushion pre-positioning strategy — dispatching the rover 30 minutes before expected onset — is the direct clinical benefit of the prediction horizon. A reactive system that detects the seizure during the ictal phase cannot pre-position protective equipment in time.
</Tip>

## TFLite Deployment on ESP32

The trained Keras model is quantized and converted to TFLite for deployment on the Vital32 ESP32-S3:

```python

# Load trained model
model = tf.keras.models.load_model('seizure_lstm.h5')

# Convert with INT8 quantization
converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]

# Representative dataset for INT8 calibration
def representative_data_gen():
    for sample in calibration_windows:   # shape (300, 5)
        yield [sample[np.newaxis, :, :].astype(np.float32)]

converter.representative_dataset = representative_data_gen
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8

tflite_model = converter.convert()

with open('seizure_lstm_int8.tflite', 'wb') as f:
    f.write(tflite_model)
```

The INT8 quantized model occupies approximately **380 KB** of flash, well within the 1.2 MB budget for TFLite Micro on the ESP32-S3. Inference time is approximately **42 ms** per 5-second tick on the dual-core ESP32-S3 at 240 MHz.

## Firebase Output Schema

```json
{
  "/lifesphere/{device_id}/vital32": {
    "seizure_prob": 0.12,
    "seizure_alert": false,
    "window_start_ts": 1718000000,
    "window_end_ts": 1718000300
  }
}
```

| Field | Type | Description |
|---|---|---|
| `seizure_prob` | `float [0,1]` | Model output for the current 5-minute rolling window |
| `seizure_alert` | `bool` | `true` if `seizure_prob > 0.85` |
| `window_start_ts` | `int` | Unix epoch of the oldest sample in the window |
| `window_end_ts` | `int` | Unix epoch of the most recent sample in the window |
